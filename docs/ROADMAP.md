# 识律 Roadmap：AI 处理领域的文本基础设施

> 定调于 2026-10-12（产品负责人）。本文是识律（lex）线的**方向锚**：描述终局、
> 盘点现状、给出战略方向与分阶段路径。它不是实施计划——每个阶段的落地仍走
> OpenSpec change 流程逐个立项。领域词汇见工作区根 `CONTEXT.md`；各能力的技术
> 契约见 `openspec/specs/` 对应 spec。

## 1. 北极星

**识律的终局 = AI 处理领域的严肃文本基础设施**：一套通用的文本处理能力底座，
覆盖法律、论文写作、剧本、公文等**严肃文本**领域，让每个领域的接入都是配置
动作而非建栈动作。

这句话的三个承重词，各自有硬含义：

- **基础设施**：不是"给某个领域做的检索工具"，而是被其他产品与领域依赖的底层
  供给。判据是——新建一个文本领域时，是否需要重新写一遍清洗/切块/嵌入/查询？
  只要还要写，就还不是基础设施。
- **AI 处理领域**：产出的直接消费者是 AI（agent 经 MCP 调用、技能预设、检索增强
  生成），不是给人翻页读的。判据是——能力是否以 MCP 工具 + provenance 契约 +
  预设包形态被 agent 可靠消费。
- **严肃文本**：法律条文、裁判文书、学术论文、剧本、政府公文——有权威来源、有
  引用纪律、有版权与合规边界的文本。判据是——能否对每条结果回答"这句话出自哪
  份文件的哪个位置、什么时候的快照"。社交媒体、网页碎片不在射程内。

一句话定位：**严肃文本的 AI 处理底座——每个领域以四件配置接入，共用同一套摄取、
切块、索引、检索与溯源契约。**

对外的官方表述（用户 2026-10-06 定，已上官网首页 `fd-official-web/src/i18n.ts:297`）：
识律 = **文本处理基础设施**（EN: Infrastructure for text processing）。

## 2. 为什么现在的地基不够

这不是谦辞，是可列举的事实。

**第一，文本中间层刚刚才有。** 2026-10-11 之前，全工作区没有跨仓共享的文本库，
只有**五套互不相通的检索栈**和**四个嵌入模型**：
`pgvector+MiniLM-384d`（fd-open-data-mcp）/ `Qdrant+Qwen3-1024d`（法律线主检索）
/ `ES+Nemotron-2048d`（law-bench）/ `sqlite-vec+bge-m3`（DAAS pdf-mcp）/
纯 ILIKE（business-mcp，`_escape_like` 复制 8 份）。
每加一个文本领域就复制一份清洗/切块/嵌入/查询代码。

**第二，引擎建起来了，但只走了全程的第一段。** `fd-text-core` 已实现
L1 摄取 → L2 结构化 → L3 索引 → L4 查询，垂域=四件配置这条守门不变量被论文与
剧本两个垂域验证过。但引擎今天是**纯只读检索型**：工具面只有
`search / semantic_search / read / presets / federated`，没有任何写入、生成、
变换或评测能力。

**第三，也是最要紧的——「基础设施」应有的横切能力还几乎是空的。** 逐项清点，
下列能力在引擎里**不存在**：

| 横切能力 | 状态 | 说明 |
|---|---|---|
| OCR | 未发现 | 无 OCR 依赖；扫描件/图片型 PDF 无入口 |
| 格式转换（PDF→文本 / docx） | 未实现 | PDF 只打标 `needs-grobid` 转交外部 sidecar，仓内无解析器 |
| 表格抽取 | 未发现 | 公文/年报/财报的表格是主体内容，无此能力等于半个盲 |
| 通用长文档结构化 | 未实现 | 只有垂域各自的解析器（论文 LaTeX/TEI、剧本幕场） |
| 实体 / 术语抽取 | 未发现 | 无文本内 NER |
| 引文解析 | **仅法律条级引用** | 学术参考文献解析未发现 |
| 去重 | 仅 hash 级 | 无语义级/近似去重 |
| 版本对照 / diff | 未发现 | `status` 只有 current/superseded 状态位，无对照能力 |
| 翻译 / 摘要 / 生成 | **全部不存在** | grep 零命中 |
| 质量评测与基准 | **仅 law-bench 合同 rubric** | 通用文本处理评测集/基准未发现 |
| 重排（rerank） | **接口位** | `querylib.py:23` `RERANK_HOOK = None`，注释自述"本期不实现" |

最后一项尤其值得单列：**法律有 law-bench 的 rubric 评测闭环，论文/剧本/公文一个
都没有。** 一个自称基础设施的底座，无法回答"我的检索在这个领域到底好不好"——
这是目前最大的空洞。

## 3. 全景图：基础设施的五层

参照柏讯 roadmap 的分层写法，把终局画成五层。左侧是层，右侧是今天的成色。

```
第⓪层 语料供给（爬虫平台 + 萬星生成/自愈 + 既有采集仓）      ← 复用，不自建
   │   fd-cn-gov（11 部委公文）/ fd-law-data（五源法律）/ fd-cn-report（披露文件）
   ↓
① 摄取层  格式适配 · 去重 · 版本退役 · zstd 冷存             ← 已实现（薄）
   │   缺：PDF/docx/OCR/表格，格式适配面只有文本与 LaTeX
   ↓
② 结构化层 域解析器接口 · 无损切块 · 元数据抽取              ← 已实现（薄）
   │   缺：通用长文档结构化、实体/引文抽取、仅 1 个切块策略
   ↓
③ 索引层  统一嵌入 · pgvector · 混合检索 · 余弦自检           ← 已实现（有硬缺口）
   │   缺：HNSW 索引未建（spec 要求建）、rerank 仅接口位
   ↓
④ 查询层  RRF 融合 · facet · provenance · 单 MCP · 预设包      ← 已实现
   ↓
⑤ 能力层  ★空白★  评测 · 写作 · 变换 · 抽取 · 对照 · 基准     ← 基础设施的真正重量在这里
   ↓
⑥ 领域层  法律 · 论文 · 剧本 · 公文 · …                       ← 已接入 2 个（论文/剧本）
```

第⑤层是本文的核心主张：**今天缺的不是又一个垂域，是垂域之上那层横切能力。**
没有它，每接一个领域仍要重复造工具；有了它，接领域的边际成本才真正趋近于"四件配置"。

## 4. 现状盘点（截至 2026-10-12）

### 4.1 引擎 fd-text-core

载体仓：`fd-text-core`（Python / FastMCP / alembic / pgvector）。守门不变量：
**接入垂域 = 交四件配置（域解析器 / 切块策略 / facet 词表 / 检索预设包），
引擎核心零改动**，CI 有路径越界检查。

| 层 | 已实现 | 成色 | 主要缺口 |
|---|---|---|---|
| ① 摄取 | hash 去重、版本退役、zstd 冷存（FDTEXTBLOCK1）、入库即挂钩嵌入 | 形态对，语料量极小 | PDF/docx/OCR/表格无入口；无文档级增量触发 |
| ② 结构化 | 无损切块不变量 + 校验器 | **只有 1 个切块策略**（SlidingWindow） | 条文式/标题式策略不存在；垂域解析器产出结构但未接回切块 |
| ③ 索引 | Qwen3-Embedding-8B（MRL 截断 1024 维）、pgvector、**HNSW 索引**（0004 迁移，2026-10-13 补齐）、余弦自检门 ≥0.999 | 完整（rerank 除外） | rerank 仅接口位（`querylib.RERANK_HOOK`） |
| ④ 查询 | tsvector ⊕ 向量 RRF(k=60)、facet、provenance 三元组、预设包、单 MCP 服务 | 完整 | 无评测/标注查询集（spec 要求"命中达标"，实际只做过单条查询） |
| ⑤ 能力 | —— | **空** | 全部：评测、写作、变换、抽取、对照、基准 |

**规模**：剧本 18 部 / 2254 块，论文 60 篇（仅元数据+摘要）。规模冒烟已补到
**156,267 chunk / 失败 0**（2026-10-13，管线吞吐与断点恢复实测；注意该数据来自
显式降级通道——见下方「当前约束」）。

**地基欠账（已于 2026-10-13 清销，见归档 change `text-foundation-remediation`）**：
- ~~质量门在 CI 上形同虚设~~ → 三值化 `PASS/FAIL/SKIPPED` + `--strict`；
  schema 漂移扩到索引（原来只查表）
- ~~`ruff` 带 `|| true` 永不失败~~ → 已删，并清掉存量 9 处 lint 违规
- ~~HNSW 索引未建~~ → 已进迁移链（`0004_hnsw_idx`，实测 10 万行 309 倍加速）
- ~~报废 CLI 入口 / README 口径 0.6B / 悬空 REGISTRY.md / ingest 重复块 /
  剧本语料口径打架~~ → 全部清销

**当前约束（2026-10-13 实测）**：SiliconFlow 嵌入账户**余额耗尽**（HTTP 402），
且舰队所有嵌入共用该账户，换 key 无效。故真嵌入通道的十万级吞吐数据尚缺，
锚点余弦检查在网内验收时为 FAIL——**充值后需重跑一次网内 `--strict` 取全绿**。

## 5. 三大战略方向

### 方向 A：补齐基础设施横切能力（第⑤层）

**这是本 roadmap 的第一优先。** 理由：法律已能卖钱，说明垂域能立项；但每接一个
新领域仍要重造工具的现状，说明底座没成型。地基的欠缺不在"又少一个垂域"，在
"垂域之上没有公共能力"。

按依赖顺序：

1. **评测层（最优先，也是最大的空洞）**——建引擎级评测：每垂域一份标注查询集，
   定期跑出命中率/MRR/关键词-vs-向量-vs-混合三通道对照，结果入报告。
   复用 law-bench 的 rubric/judge 框架（走契约，不搬仓）。**没有评测就无法宣称
   基础设施**，也无法在换嵌入模型/加垂域时证明无回归。
2. **抽取与结构化**——实体/术语抽取、引文解析（先把法律的条级引用能力泛化出垂域
   无关的接口）、通用长文档结构化（吸收 `fd-cn-report` 的抽取经验）。
3. **格式面**——PDF→文本、docx、表格抽取、OCR（按领域需求排序：
   公文 PDF > 年报表格 > 扫描件 OCR）。收敛 DAAS `pdf-mcp` 与论文的 GROBID 两条
   互不相通的解析路径。
4. **变换与对照**——去重的语义级版本、版本对照/diff（法规修订、论文版本、
   公文废止都硬需要）。
5. **rerank 落地**——`RERANK_HOOK` 从接口位转为真实能力（与评测层绑定：
   重排的收益由评测集量化，不靠感觉）。

### 方向 B：垂域扩面 —— 公文立项 + 法律回迁

- **公文垂域（近期立项）**：采集层现成（`fd-cn-gov` 11 部委 + `fd-law-data`
  gov-rules 国务院规章库）。四件配置里的解析器是主要工作量——公文有强结构
  （文号/标题/主送/正文/落款/附件），正好考验域解析器接口。**注意中文分词硬约束**：
  zhparser 在引擎实例不可得（`INFRA-NOTES.md`），目前靠引擎原生 CJK bigram 承担。
- **法律回迁（中期，独立立项 `law-line-consolidation`）**：引擎侧已声明"不背
  wenshu 迁移义务"，wenshu 永不回迁、用户另行处理。可回迁的是法条/规章/指导案例
  一线。障碍实数：Qdrant 36.5 万点、条级引用硬依赖（`law_reference` 是
  legal-concept-map 技能的唯一依赖）、双栈灰度观察期。**以季度计，容忍双栈共存。**
- **论文写作（近期）**：把 `docs/text-presets/skills/paper-*` 三个预设升为引擎能力
  或明确其归属——今天"论文写作"只是技能层，不是引擎能力，这个界限要说清。

### 方向 C：清债与守门（贯穿全程，不可延后）

基础设施的可信度靠守门，不靠功能数量。第一阶段必须清掉：

1. **把质量门恢复为真的门**：CI 里 `ruff || true` 去掉；conformance 门的四项 DB
   检查要么在网内 runner 跑、要么在 CI 上硬失败——**"跳过"不能算通过**。
2. **清工程债**：报废 CLI 入口、README 与代码口径、剧本语料 15-vs-18 打架、
   注释错字、重复代码块。
3. **补索引**：建 HNSW（spec `text-indexing-search` 明文要求 `vector(1024) cosine
   + HNSW`，迁移链里没有），照 `fd-open-data-mcp` 的双读校验手法做切换验证。
4. **规模就绪补课**：把 54,000 chunk 的冒烟补到 tasks 原文的 10-50 万级，
   拿真实吞吐数据。

## 6. 立场与红线（跨方向不变）

1. **版权按领域分层，不统一放宽**：法律=政府公开可自有；剧本=公版经典可自有
   （含老舍 2017 起大陆公版）；论文=**有版权，不自建大库**，全文仅内部索引处理、
   对外只出元数据 + 切块引用 + 原文链接；戏考转录本权属存疑则如实标注。
2. **provenance 三元组永不省略**（`source` / `stable_id` / `as_of`）：每条结果必带。
3. **诚实降级，不拿半份结果冒充完整**：上游失联返回结构化错误并说明缺哪个依赖。
4. **接入垂域不改引擎核心**：这是线级不变量，CI 路径越界检查守着；垂域需求若
   需要改引擎，先修引擎抽象再接垂域（spec 明文）。
5. **单一嵌入模型、单一向量库**：不许出现第二个向量后端。
6. **接入即评测，不先宣称**：能力上线同批配文档与评测集数字，不先宣称（照
   content-integrity 纪律）。
7. **法律线商业面不因引擎重构中断**：法律回迁走双栈共存与灰度，不是切换。

## 7. 分阶段路径（方向序，非日历承诺）

- **近期（地基清债 + 第一块能力）**：
  ~~质量门恢复为真门~~、~~清工程债五项~~、~~建 HNSW 索引并做双读校验~~、
  ~~规模冒烟补到 10 万 chunk~~（以上四项 2026-10-13 全部完成并归档，
  change `text-foundation-remediation`；规模冒烟的完整吞吐数据来自显式降级通道，
  真嵌入通道待账户充值后补测）；
  余下：**评测层立项**（标注查询集 + 三通道对照 + 定期跑）；**公文垂域立项**。
- **中期**：抽取与结构化（实体/引文/长文档）；格式面（PDF/docx → 表格 → OCR）；
  法律回迁 `law-line-consolidation`（双栈共存，季度级）；论文写作能力归属落定；
  ~~剧本语料口径统一~~（已完成）→ 转为「修脚本与库的漂移」；rerank 由评测集驱动落地。
- **远期决策点**：变换与版本对照；更多严肃文本领域（条约、标准、专利、招标、
  政策文件）；引擎对外 gateway 与计量（v1 明确不做，由网关侧承接）；
  模型层（法律微调模型的重训与量化，受训练数据 lineage 审计门槛约束——
  **先重训后量化**，未重训前量化无意义）。
